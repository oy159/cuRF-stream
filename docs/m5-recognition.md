# M5：识别质量复查

2026-11-18。**识别质量未通过，M5 不能按可用系统交付。** 此结论取代此前仅以现场出现标签、
零丢样和完成视频为依据的完成判断。[上一轮记录](m5-dsss.md) 的运行数据仍然有效，不能据此推导识别质量合格。

## 已修复的确定缺陷

- 显示端此前先按轨迹每 200 ms 保留最后一条模型观察，再投票，丢掉了短突发和确认票。
  现在完整模型流逐条判决，之后仅合并重复的未识别更新；所有已确认 / 滞回结果、瀑布行和 ADS-B 消息均保留。
  原始概率不改写，页面累计数明确使用完整原始判决，未知记录不会因显示压缩从总计中消失。
- 找回完整宽组件后，原实现还继续分类历史窄轨迹的人为切片。现在当前连通宽组件只提交一次，旧窄轨迹暂不刷新；
  检测再次分开后仍可恢复。两个已经建立的宽邻居不符合三倍宽度条件，保留独立轨迹。
  单条窄历史也不能继续锁住后来的宽提取；宽组件复用的区间交并比从 0.70 收紧到 0.85，减少跨组件串轨。
- 同一轨迹在一跳中关联到多个检测片段时，带宽估计请求现在同步扩大到实际联合范围，避免只测量第一个片段。

这些是提取和证据处理的修复，没有更换 run4 权重，也没有降低识别置信门限。
冻结策略配置 SHA-256 仍为 `258210c3ba6879950cf4a3ff5bb58c2ac70ac424d93e01590c509678c1b3235f`。

## 仍然存在的实采漏识别

固定的新录音在 RX2、2450 MHz、61.44 MS/s、模拟带宽 56 MHz、手动增益 20 dB 下采集，ADC 削顶比例为 0。
独立 Barker-11 检查在同一秒 IQ 中得到：

| RF 中心 | 最大相干能量比例 | 超过 0.5 的 64 µs 观察 |
|---|---:|---:|
| 2442 MHz | 0.9764 | 952 / 15624 |
| 2462 MHz | 0.9209 | 64 / 15624 |

组件合并版完整回放该录音，573 条模型观察全部未命名，两个目标均无确认标签。
这是明确需要继续处理的实采正控制样例。Barker 检查是独立的物理层诊断，不是 PLCP/FCS 解码，
不能用这一个样例报告总体实采准确率。

30 秒中心频率对照也未解决整体问题：2440 MHz 单路原始未知比例为 97.99%，2450 MHz 单路为 98.26%，
2450 MHz 双路为 98.57%。完整模型输入 / 显示输出分别为 15638/6911、15383/6629、18210/8146；
页面与结束记录仍累计完整模型判决。三场均零驱动异常、零丢样 / 缺口、零二级跳过，`tx_samples=0`，
显示读取峰值积压 13431 / 16309 / 17873 字节，宽带处理 p99 为 4.72 / 4.81 / 6.72 ms。
这些短测验证完整判决没有重新阻塞接收，不能替代 300 秒长测或实采质量验收。

移到 2450 MHz 后，原来约 2457.5 MHz 的边缘候选变为约 2462 MHz 的宽 DSSS 命名观察，支持带边截断的诊断。
但原 2442 MHz 载波仍不能稳定命名，整体未知比例也未下降。两场实采发生在不同时间，不能把差值当作受控准确率比较。
默认中心仍为 2440 MHz，新增 `--ism-center-mhz` 仅用于明确记录调谐对照。

## 未采用的中心修正试验

还发现宽轨迹会一直保持最初的中心估计：起始观察偏了五六百 kHz，即使后续完整观察更准确，
也可能持续被 500 kHz 的 WiFi 栅格检查拒绝。尝试在完整宽观察中按源时间以 0.2 秒时间常数平滑修正中心，
保持窄带累积逻辑和置信门限不变。上述 1 秒实采中的 2442 MHz 因此从 0 条变为 4 条命名，2462 MHz 仍未确认。

但完整 M4 回归出现退步：1657 条命名中有 1 条错误，高 SNR 覆盖从 79/91 降为 77/91，
真值正样本的未识别观察比例升至 54.91%。尽管原 M4 的错误率 / 数量门槛仍通过，且新增中心收敛测试通过，
**这项试验不纳入交付代码**。错误标签和丢失的已知载波不能因为某一段实采改善而被忽略。
试验代码、二进制、测试和失败对照保留在 `m4_centres`、`capture2450/centre_tracking` 与 `centres.patch`，不冒充通过版本。

## 本轮验证

交付代码通过原 C++ 58/58、Python 57/57、104 场 M4 全部运行 / 标签 / 负样本检查，以及完整判决与显示输出的对照检查。
组件测试覆盖单条窄历史、多个碎片、原有宽邻居、宽突发消失后窄轨迹恢复与带外独立窄邻居。
Chrome 中检查了演示 / 工程模式与 390 px 窄屏，页面无脚本错误或横向溢出，静态 UI 审计无发现。
中心平滑试验另外通过了 59 项 C++ 测试，但因真实覆盖退步被拒绝；不能把单元测试通过等同于识别质量合格。

## 后续质量工作与验收边界

优先解决完整宽载波的定位、相邻 / 重叠宽候选分离以及实际进入模型的窗口，先用同一份 IQ 固定复现。
完整载波仍无法识别时，再评估模型与实采数据的分布差异。不能把碎片分类失败直接解释为模型需要重训。

50 Ω 噪声 / 杂散校准还需要真正的终端负载；RX1 接未工作的 TX 会泄漏空中信号，不能作为噪声参考。
在获得有效参考前，不把未命名候选武断地归为本机杂散，也不伪造校准表。

后续验收须同时报告原始候选未知总量、带真值载波覆盖、已知完整实采载波的漏识别与标签空窗，
并继续保留每频段最少命名数量、错误率低于 2%、负样本和运行检查。零丢样、偶尔出现目标标签和演示录像
都不能单独证明识别质量合格。

证据位于远端 `~/dataset/m5_quality_v3`，本机摘要在 `docs/results/m5-quality-v3`。实验数据、模型、缓存和媒体不提交 Git。
