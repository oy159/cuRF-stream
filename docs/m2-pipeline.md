# M2：信号级实时链路

2026-11-17。本阶段把已验证的提取器接进检测、跟踪、切窗和第二级引擎，并用受控回放验收。它不包含 M3 的显示策略，也不把合成回放结果当作实采结论。

## 模型与运行方式

第二级采用 `s2_run4`，结构继续冻结：3×1024 输入，13 类，351341 参数。它在同一份 ds_v5 验证集上的总准确率为 91.55%，≥10 dB 为 95.91%；run3 在这份数据上分别为 89.29% 和 94.23%。ds_v5 已适配 2B–3B 采样率档位。

默认先使用 FP16。`--stage2-int8` 使用同一引擎的 INT8 路径；三通道输入不走写死两通道的 stem 融合。远端已保存导出物到 `~/work/cuRF-Stream/model/artifacts/s2_run4/export`。

```sh
build/cuda-release/bench/curf_classify \
  --source file --file capture.p12 --streams 2 --loop --realtime --drop --seconds 300 \
  --stage2 model/artifacts/s2_run4/export --band-mhz 44 --ui-out /tmp/signals.feed
```

有 `--stage2` 时，第一级默认只做信道化和检测，既不加载第一级模型，也不构造第一级引擎。`--stage1-classify` 可额外恢复逐信道分类。原有未启用第二级的命令继续使用逐信道引擎。

## 检测和跟踪

- 第一级把 1024 个信道采样分成 16 个时间片，使用片内峰值做活跃检测；窗口平均功率继续用于 RMS 和功率显示。默认每片约 267 µs，短突发不会再被整个 4.27 ms 窗口平均掉。
- 忽略初次启动时 PFB 尚未填满历史的帧，避免启动瞬态产生一整片假信号。
- 每路分别合并相邻活跃信道。已有载波先参与关联；一个候选区临时连接几个已知载波时，按它们之前的频带间隔划分，防止窄带 track 被拉到邻近 LTE 上。
- 对新候选区做细谱估计；对已知窄带载波，把精扫限制在已有中心附近。宽带载波保持完整粗候选区，避免递归地在上一轮占用带宽内部精扫，最终收缩到 OFDM 资源块或一个 FSK 频率。
- 噪声从额外频带的边缘估计，扣除噪声后测 99% 占用带宽。带宽保留按源时间计算的 2 秒衰减包络，减少话音停顿、资源分配变化对采样率和模型带宽通道的扰动。中心在载波范围内保持稳定；这属于输入信号的跟踪，不修改模型概率。
- 轨迹超时约 200 ms；默认每个窗口最多提交 64 个候选信号。容量不足、忙碌、原始数据覆盖分别计数。

窄带检测仍受粗信道能量门限约束；它不是独立的高灵敏度窄带搜台器。验收场景给窄带源足够的信噪比，复杂弱邻道场景继续用真值单独评估。

## 共享 FFT 滤波器组

单个 hop 是 2^18 个原始样点，在 61.44 MS/s 下为 4.267 ms。默认 packed-wire 环保留 48 个 2^17 块，约 102.4 ms；每个 RX 约 18 MiB。

1. 读取当前 hop 和前三个 hop，按 RX 解包成复数；采集开始前的历史定义为零，已经覆盖或出现缺口的历史不能充当连续数据。
2. 每个 RX 做一次 4×hop 的共享前向 FFT。细谱估计的频率分辨率约 58.6 Hz。
3. 每个信号选 W∈{16,24,32,48,…,hop}，输出采样率为 W×fs/hop，通常为带宽的 2–3 倍；输入采样率上限、最低档位和攒窗期间的档位保持会形成边界情况。
4. 对 W/hop=L/Q，使用 32Q+1 tap 的 Blackman FIR，归一化截止频率为 0.375 倍输出采样率，增益为 L。通过频谱复制和混叠求和实现有理数抽取，不显式插入零。
5. 同尺寸信号按固定 batch 档位做小 IFFT。每行有 4W 个样点，丢弃前三个 hop 的无效区，只取最后 W 个有效样点；再按绝对样点时间混频。

FIR 群延迟为 16 个输出样点。响应缓存保留到 ±8 倍输出采样率，省掉远端极小的频率尾部；误差通过直接连续 FIR 参考验证，不能把该近似当作理想砖墙滤波。

FFT plans 按有限的 W/batch 集合初始化。它们共享最大工作区，避免为每个 plan 重复持有 workspace；热路径不创建 plan 或分配设备缓冲。批量填充行不会参与结果计算。测试覆盖了三行请求向四行 batch 补齐、两个 RX、有理数比率和块边界。

## 切窗、时间和背压

- 宽信号在一个有效 hop 的 64 个候选位置中选择能量较高的 1024 点片段；这不保证每个短包都产生一次分类，包级漏检另行统计。
- 窄信号连续追加数据，满 1024 点后保留余量；例如 W=96 不再把每 11 个 hop 多出的 32 点丢掉。频率、采样率或连续性改变时重置积累。
- 输入仍是单位 RMS 的 `[1024][3]`：I、Q、`(log10(B)-5)/2`。
- 异步请求的主机描述符存放在 pending 槽自己的锁页内存里，避免临时 vector 在 DMA 完成前失效。
- `processing_ms` 从最终 raw hop 进入主机 ring 算到第二级结果返回，包含检测、提取和推理；`observation_ms=1024/fs_out` 单列。宽、窄的处理延迟分别输出 p50/p99/p999/max，不能用第一级的延迟代替。
- `t0`/`t1` 是模型窗口在源样点时间中的区间，已扣除 FIR 群延迟。零历史启动时 t0 可以为负。它们不是主机时钟。
- 实时模式只轮询第二级；离线文件回放可以有限背压，避免主流水线跑得更快而静默跳过第二级窗口。结束时统一 flush，第二级尾部计入总运行时间。
- `FileSource --realtime` 现在按样点时钟限速，支持循环回放和 restart；可以测整个链路的长期实时性。

`SignalStageConfig::on_input` 是可选的诊断回调，返回实际进入引擎的 `[L][3]`。正常运行不做这份 D2H。测试将窄带模型窗口与 CPU 连续卷积后的切窗、归一化结果对齐，包括余量衔接和带宽通道，误差门限为 5e-5；滤波器组本身的 IQ 门限为 3e-6。

## 一键复现验收

在 CUDA 主机上，使用已导出的 run4 模型和 OnAir/自研 FM 源：

```sh
cmake --preset cuda-release -DCURF_TENSORRT=OFF -DCURF_CUDNN=OFF -DCURF_CUTLASS=OFF
cmake --build build/cuda-release --target curf_classify curf_tests_cuda curf_tests_cpu -j 4
ctest --preset cuda-release
python -m unittest discover -s tests -p test_scene_score.py
python tools/run_signal_checks.py \
  --bin build/cuda-release/bench/curf_classify \
  --model model/artifacts/s2_run4/export \
  --src ~/dataset/onair --emissions ~/dataset/ds_v5/emissions.json \
  --out ~/dataset/m2_acceptance --seconds 300
```

脚本放入 WiFi OFDM、BLE、LTE 5 MHz 和窄带 FM，输入带内 SNR 为 25–30 dB。先检查 0.5 秒单路回放，再把每帧复制成两个交织 RX，按双路 61.44 MS/s 限速，循环运行 300 秒。这是相同受控负载的双路压力测试，不代表两个天线的独立空中流量。

输出包含：源数据和带时间的 truth、有限回放的原始分类评分、长测 JSON/feed、验收结果和执行命令。M2 验收要求：零丢样、零样点缺口、零第二级跳过、8 个预期载波全部出现、轨迹不跨载波、宽窄处理 p99 均小于 15 ms。中心误差不超过 max(5 kHz, 0.2B)，带宽在真值的 0.25–4 倍内，防止收缩到一个局部分量。额外未匹配候选单独计数，不能把它们算作样点丢失或正确识别。失败返回非零。

`model/make_scene.py score` 现在同时检查时间和频率重叠，拒绝过宽结果匹配窄载波，也拒绝缺少结束记录的 feed。truth 记录了源录音循环时每次发射的时间；短突发的边缘从干净源采样的功率确定，避免把 STFT 帧边界直接当作精确时间。旧版无时间 truth 需重新生成。

分类评分针对有限、不循环的场景。长测的静态载波关联由 `tools/check_signal_tracks.py` 检查，不能拿超过原始场景时长的循环 feed 直接与单周期时间 truth 打分。
